🛠️ Synthesized Scoped Terraform (Least-Privilege Patch)

Patch for AP-001 Blast radius reduced from 100% of all tenant cryptographic keys to exactly 1 authorized CMK (99.9% containment).

AI-CSPM analyzed the cross-layer DAG linking the Kubernetes container 'payment-processor-deployment' (via IRSA ServiceAccount) to the AWS KMS Key 'payment_key' and S3 Bucket 'payment_vault'. The original policy used a wildcard Resource ('*'), granting the container workload unrestricted ability to decrypt ANY encrypted database or bucket in the account. The synthesized remediation enforces two critical security controls: 1. Scoped Resource ARN: Decryption is restricted exclusively to the specific Customer Managed Key (CMK) ARN for 'payment_key'. 2. Cryptographic EncryptionContext Condition: Decryption is cryptographically tied to requests originating strictly for the 'payment_vault' S3 storage vault.

resource "aws_iam_policy" "scoped_payment_kms_policy" {
  name        = "ScopedPaymentKmsPolicy"
  description = "Remediated by AI-CSPM: Strictly scoped to payment_key ARN with S3 EncryptionContext constraint"

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Sid    = "ScopedKeyDecryptionOnly"
        Effect = "Allow"
        Action = [
          "kms:Decrypt",
          "kms:DescribeKey"
        ]
        # REMEDIATED: Replaced '*' with explicit Customer Managed Key ARN
        Resource = aws_kms_key.payment_key.arn

        # REMEDIATED: Cryptographic binding strictly to authorized S3 vault
        Condition = {
          StringLike = {
            "kms:EncryptionContext:aws:s3:arn" = [
              aws_s3_bucket.payment_vault.arn,
              "${aws_s3_bucket.payment_vault.arn}/*"
            ]
          }
        }
      }
    ]
  })
}

resource "aws_iam_role_policy_attachment" "scoped_payment_kms_policy_attach" {
  role       = aws_iam_role.eks_payment_kms_role.name
  policy_arn = aws_iam_policy.scoped_payment_kms_policy.arn
}
